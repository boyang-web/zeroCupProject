本轮目标：用可运行的小样评估视觉、氛围、粒子转场和用户之间的轻互动。内容暂拟为《留一盏灯》，可在后续由用户整体替换，不代表最终故事。

## 任务分块

| 模块 | 本轮交付 | 正式制作时的工作 | 验收重点 |
| --- | --- | --- | --- |
| 内容与分镜 | 晨起／歇脚／归来三幕、临时对白、访客角色 | 用户确定故事、人物、地点与叙事节奏 | 少量文字也能看懂情绪和行动意义 |
| 美术资产 | 三时段虚构写实氛围图 | 实拍取材；选择摄影测量、3DGS 或建模；清理与优化资产 | 生活细节可信，画面统一，主体清楚 |
| 音乐与环境声 | 原创程序合成试听、声量开关、交互音 | 实地录音、正式音乐、分层混音与空间定位 | 声音支持氛围，开启关闭自然，不压过内容 |
| 三维空间 | 可旋转、缩放的小店几何草模 | 实景资产接入、镜头、物体交互、遮挡与灯光 | 可探索范围清楚，视角移动不露出未采集区域 |
| 粒子转场 | 概念图采样为约 10 万点，GPU 变换与重组 | 验证实景 splat／模型之间的转场，编排路径与时序 | 形态可辨、衔接自然、性能稳定 |
| 用户参与 | 留灯、留纸条、下一位访客读到 | 将可见反馈进一步绑定场景内灯具和桌面物件 | 动作改变环境或他人体验，反馈明确 |
| 后端与持久化 | Python + SQLite，本地多浏览器共享、去重、轮询 | 选定正式部署环境，完善必要的数据管理与同步 | 刷新保留；另一用户能读取；错误有反馈 |
| 适配与交付 | 自适应草稿、操作说明、接口烟测 | Chrome 129 验证、手机与慢网优化、原创及库清单、匿名包 | 全流程能演示，资料可审查 |

## 后续推进顺序

1. 先评审本轮演示的情绪、美术方向、转场节奏和互动意义。
2. 确定内容后，采集一个小店或摊位，验证一种实景重建路线。
3. 将一个正式实景资产替换进演示，验证浏览器画质、加载和帧率。
4. 打通两个实景的转场，再扩展叙事与多人互动。
5. 完成声音、适配、文档与比赛打包。
