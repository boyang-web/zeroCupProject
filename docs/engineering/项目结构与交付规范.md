# 项目结构与比赛交付规范

2026-11-11：以远端 main 的 d029edf 为业务基线，快进同步首页“新的归途”和重玩确认；没有合入本地未提交业务内容。

## 正式工程

保留远端目录，避免为交付移动源码并破坏资源路径。`src/core` 管纯规则，`content` 管剧情和资产，`runtime` 管装配，`features` 管功能，`presentation` 与 `styles` 管表现，`infrastructure` 管存储与声音，`shared` 管通用组件。`public/assets` 是运行资源，`tests` 是验证，`scripts` 是工具，`docs` 是文档。

`archive`、`references`、原始压缩包与比赛要求原件留存，不属于运行依赖。`node_modules`、`.tools`、`.tmp`、`dist` 和 `submission` 是本机或生成目录，不上传为正式源码。原图不改不删。

## 提交结构

总 ZIP 只含完整、匿名两个子 ZIP，名称按选手手册使用队伍和队长信息。子包解压后直接看到 README.md、package.json、src、public、dist、tests、scripts、docs、third_party_licenses，不再多套项目目录。

两个版本使用同一套游戏源码和成品；完整版 README 包含风栖林、蔺博洋、王子萌，匿名版删除队伍及个人信息。第三方作者的法定版权与字体 OFL 保留。包内说明功能库与用途、自适应规格、主题、运行方法和素材工具。无后端、CMS 或预设样式库。

`python scripts/package-submission.py` 以白名单创建隔离副本、等尺寸压缩资源并重新检查构建。`python scripts/finalize-submission.py submission/<时间戳>` 在本轮验证记录完成后生成压缩包、匿名扫描与 SHA-256。不复用旧候选包。

打包前拒绝未提交的运行源码、资源或配置变更；生成记录包含业务提交和测试数量。包内保留可独立运行的 dist，无需 npm 安装；开发审查可 npm ci 后运行检查。所有原图留在正式工程。

## 比赛要求依据

已阅读“比赛要求”内的选手手册及开幕式评分 PPT。按手册准备完整与匿名双包，README 列成员、非自写库和用途；选自适应界面，构建目标 Chrome 129。手册截止 11 月 14 日 22:00，PPT 日期有差异，按较早日期安排。PPT 提及 IE，但当前工程不支持 IE，实际浏览器与未验证范围明确记录，不把构建目标当实测。

本轮生产成品实测发现首页书本的 CSS 自定义属性引用相对纸纹路径时请求到 assets/assets；参照引子已有实现，以 document.baseURI 解析成绝对资源 URL。仅新增此项必要修复，未恢复旧未提交业务内容。

根目录整理：原始 `归档.zip` 移入 `archive/original-packages/`，`本地最新版本` 移入 `archive/local-snapshots/`，`比赛要求` 移入 `references/competition/`。根目录保留最终总 ZIP 的校验一致副本；其余打包副本、截图和验收数据留在 submission。原 README 详细历史保留于 docs/history/根目录说明-20261111.md。此轮仅整理文件与文档，没有变更游戏内容，已验证的提交包保持字节不变。
