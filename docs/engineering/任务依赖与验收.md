# 任务依赖与验收

先跑通占位，再用第一家店的完整体验验证框架。以下是协作切分，不预设人员或排期。

| 任务 | 输入／前置依赖 | 输出 | 验收 |
| --- | --- | --- | --- |
| 五章流程与规则 | 最新五章约定、核心玩法 | 章节、条件、任务、奖励与分支 | 主流程可通，局部失败仍可进第五章，结局可达 |
| 第一家店事件 | 基础框架、人物关系草案 | 对话、关键选择、线索与道具表 | 主线信息充分，选择有依据，错过支线可继续 |
| 物件玩法 | 关键物件、动作与目标 | 独立小游戏组件 | 完成、失败重试、取消、帮助、退出均可用 |
| 场景构图 | 第一家店互动点与视觉方向 | 场景草图、特写、热点位置 | 物件能辨认，文字与热点不遮挡，窄屏有方案 |
| 存档与恢复 | 稳定状态契约 | 版本化存档与错误反馈 | 选择前恢复、奖励不重复、坏档不覆盖、存储失败不崩溃 |
| 手记与道具 | 信息与奖励表 | 百味录、背包、跨章补记 | 信息只在获得后出现，道具用途和结果可理解 |
| 联合试玩 | 第一家店上述内容可运行 | 问题清单与修改优先级 | 判断哪里不清楚、哪里好玩、何处单调，不以编译结果代替 |
| 扩展余下章节 | 第一家店接口验证、后续故事骨架 | 三店与主角贯穿线 | 章间区别明确，伏笔可回溯，结局回应过程 |

故事草案、玩法动作草图与美术风格探索可同时推进；正式图像和详细交互布局依赖构图与内容确认。新故事与新玩法整合前，应先检查模块约定，避免各自建立另一份状态。

自动检查包括类型、引用、状态变化、奖励与存档。人工试玩负责故事理解、美术、节奏、幽默、操作舒适度，以及真实浏览器／设备／声音表现。
