# 本机浏览器预览

2026-11-06。用户已明确授权调用本机浏览器进行游戏预览与验证。本轮使用本机 Chrome 和现有 Windows Computer Use 工具，完成实际点击、拖动、键盘和截图检查。

## macOS 启动

双击根目录 `START.command` 即可启动。脚本支持包含中文和空格的工程路径，不依赖 Finder 的工作目录或终端 PATH；优先使用工程内 Node 24.15.0，其次查找系统 Node。缺少依赖时自动安装，版本不足或安装失败会停留在终端显示原因。

浏览器按 Chrome、Edge 顺序查找 `/Applications` 和用户 `Applications`；没有时调用 macOS 默认浏览器。Chrome／Edge 使用独立预览目录，默认浏览器使用自身存档。游玩期间保留终端，按 Ctrl+C 停止本次启动的服务。可用 `./START.command --no-open --port 5174` 只启动指定端口。

## 入口

```sh
npm run preview:local
```

脚本会启动或复用 `http://127.0.0.1:5173/` 的本工程 Vite 服务，再打开本机 Chrome；没有 Chrome 时查找 Edge。浏览器使用工程内 `.tmp/local-browser-profile`，其中的存档和日常浏览器分开。脚本新启动服务时保持终端运行，按 Ctrl+C 结束服务；复用已有服务时不会接管或关闭它。

```sh
npm run preview:local -- --port 5174
npm run preview:local -- --no-open
```

第一个命令换端口，第二个只启动或检查服务。需要指定其他安装位置时，可使用 `BAIWEI_BROWSER_PATH`。普通 `npm run dev` 和构建预览入口仍可继续使用。

## 本轮连接问题的证据

内置通道在最简单的执行检查中也返回 `codex/sandbox-state-meta: missing field sandboxPolicy`，发生在页面操作之前；重置执行环境后仍相同。本机 Vite 页面可正常返回 200。

本地配置把执行组件固定到旧 `node_repl.exe`，其配套 `CODEX_CLI_PATH` 为 0.133.0，而当前后台为 0.167.0。检查发现旧组件要求 `sandboxPolicy`，当前后台的相关结构采用 `permissionProfile`，证据指向权限协议版本不一致。

曾尝试官方应用更新：商店命令未返回升级，商店包下载要求企业管理员认证。随后通过 [OpenAI 官方 Windows 部署文档](https://learn.chatgpt.com/docs/enterprise/windows-deployment)取得签名有效的新包作诊断，但没有安装该包，也没有改写全局 Codex 配置。实际交付的预览验证使用上面的本机浏览器入口。

## 验证方法

先运行预览入口，取得页面响应，再观察标题为“百味录”的独立浏览器窗口。以新截图或界面树定位按钮，依次验证首页、第一章物件和视角；缩小窗口后再次检查布局。窗口重新打开后应重新取得窗口标识，不复用上次的进程号或截图坐标。

真实浏览器截图保存在 `docs/art/previews/`。HTTP 成功、类型检查和构建成功分别记录，不能代替实际画面与操作验证。当前已实测 Chrome；Edge 作为脚本中的可选入口，尚未独立验收。

2026-11-07：桌面锁屏后，Computer Use 能截图窗口但不能对被锁屏覆盖的窗口点击。本轮改用机器已有的 Python Playwright 启动独立无头 Chrome，显式保留 Chromium 沙箱，继续验证 localhost 的真实渲染与交互。使用隔离上下文和规则层生成、经存档仓库验证的普通模式自动档，通过首页“继续故事”载入；不使用日常浏览器资料，不解锁桌面或修改安全设置。普通试玩入口仍只需要 Node 与本机浏览器，不把这项验证工具变成游戏运行依赖。

内置通道再次出现同样的协议错误时，记录一次诊断并沿已获授权的本机预览路径继续工作。不要把反复尝试相同连接当作浏览器验收，也不因这个错误降低沙箱限制。
