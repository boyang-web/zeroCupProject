# 《百味录》游戏策划文档 v0.1

整理日期：2026-11-05。工作名称暂用《百味录》，正式名称待定。

> 后续更新：当前阶段暂不定稿，议题与制作约束见 [议题清单](../议题清单.md)。用户最新明确总共五章：第一章背景、第二至四章三家小馆、第五章多结局。下文“序章／终章”属于功能称呼，均计入五章，不是额外章节。

本文根据本轮讨论整理，供团队确认故事、玩法和内容范围。暂不决定技术架构、开发排期或资源实现方式，也不据此开始改动现有工程。

文中使用三类标记：**已确认**来自本轮明确描述；**建议**是为使体验成立补充的方案；**待定**需要团队进一步创作或选择。未标为已确认的具体人物、情节、数值与数量，均不是定稿。

## 一、游戏定位与体验目标

**已确认：**这是一款以归乡为起点，通过角色扮演、情景对话、场景探索和物件小游戏展开的叙事游戏。玩家接受祖母委托，依次走访三家小馆，补全《百味录》。探索所得和行动选择会改变人物关系、章节走向与最终结局。

三家小馆的主题分别是：

1. 小店里的烟火气与家庭温情。
2. 现代化发展与老店、熟客经营模式之间的碰撞。
3. 一家深夜为都市夜归人提供晚餐的特殊小馆。

主角自身的故事贯穿其中，构成第四条叙事线，不必另设第四家店或独立探索章节。

希望玩家经历的过程是：起初带着“替祖母办完这件事”的目的进店；因为物件、人物和小小的异常产生好奇；在交谈与动手中逐渐了解各人的处境；做出有代价的选择；最后决定自己如何记录这些人，又如何回应自己的生活。

**建议的主题表达：**食物连接着具体的人，而关心一个人，需要了解他的处境、意愿与生活边界。家庭温情、经营变化、夜间互助各有现实代价。作品允许温暖，也允许误解、疲惫和未能解决的事情。

价值观通过人物行动及后果呈现，避免由结尾旁白替玩家概括唯一正确答案。

## 二、把目前尚不明确的地方说明白

| 议题 | 当前可以明确的含义 | 建议补充的规则／仍待决定的内容 |
| --- | --- | --- |
| 角色扮演 | 玩家以归乡人的身份参与故事 | 建议采用有既定过去的主角，允许玩家选择当下态度与行动；是否自定义姓名、身份细节待定 |
| 祖母的委托 | 补全《百味录》是主线动机 | 为什么现在补、为什么找主角、补完交给谁、祖母是否在场，均待定；不预设祖母已经去世 |
| 《百味录》 | 是贯穿三店的核心载体 | 建议同时收录食物、人物、物件与玩家写下的理解；“补全”不等于找到所有隐藏内容 |
| 三章顺序 | 依次走访三家小馆 | 建议主线固定顺序，章内自由探索；是否跨日、能否回访需明确 |
| 人物群像 | 出场人物都应有自己的作用 | 每人至少具有自己的需要、与他人的关系、影响玩家理解或事件发展的行为；不要求每人拥有独立长支线 |
| 碎片叙事 | 信息分布在对话、物件和跨场景联系中 | 主线因果必须可理解；可选碎片用来深化或修正理解，不能把基本信息全部藏起来 |
| 章节属性 | 每章积累不同属性并影响剧情 | 需要定义属性的含义、来源、使用时点、是否显示；不直接沿用旧稿统一双数值 |
| 小游戏 | 围绕关键物件展开 | 应让玩家体验人物的劳动或处境；不是每次点物件都强制进入小游戏 |
| 道具软锁 | 部分道具帮助区域探索 | 建议缺少道具时仍可用较费事的替代办法通过；唯一钥匙才能开启的门属于硬锁，需区别标注 |
| 不可撤销选择 | 有些行动会产生持续后果 | 建议指当前存档分支内不能随意撤回；读旧档是否允许改选须明确 |
| 任务失败 | 某些选择会失去一个目标 | 建议主要体现为局部任务失败，仍能继续主线；是否存在整局失败待定 |
| 多结局 | 见闻、属性与选择共同影响结局 | 需要区分每家店的局部结果与主角的最终去向，避免所有变化压缩成一个总分 |
| 大量互动 | 场景中有许多可操作的物品 | 建议区分关键、补充与生活反馈；数量应服从信息密度和操作舒适度 |
| 音乐与 Wiki | 相对次要的补充内容 | 音乐承担氛围与反馈；Wiki区分玩家查询与团队创作资料，避免默认展示剧透 |

这些规则中，祖母与主角的关系、《百味录》的用途、三章核心冲突和结局依据，应优先于数值阈值定稿。

## 三、整体叙事结构

### 3.1 主流程

序章：归乡、接到委托、拿到有空页的《百味录》 → 第一章：家庭小店 → 第二章：老店与新经营方式 → 第三章：深夜小馆 → 终章：整理记录、回应祖母、决定下一步。

**建议：**使用清晨、白天、深夜的时间变化组织三章，形成情绪递进。具体是一日之内还是连续数日，须根据人物行动的可信度决定；经营变化的结果可以在尾声以“后来”呈现，不让一次谈话当天解决长期经营问题。

| 阶段 | 玩家眼前的目标 | 叙事作用 | 主角线的推进 |
| --- | --- | --- | --- |
| 序章 | 弄清委托，找到第一家店 | 建立归乡的陌生感与好奇心 | 主角认为自己只是回来办事 |
| 第一章 | 记录一道熟悉的食物，参与一次开店劳动 | 从亲切表面进入家人之间的真实分歧 | 意识到“为你好”和“听你说”有区别 |
| 第二章 | 了解经营难题，协助一次具体尝试 | 看到不同需要如何碰撞 | 开始面对自己离开故乡时的判断 |
| 第三章 | 在深夜参与一次接待或收尾 | 将关心落实为有边界的行动 | 发现自己也曾是需要一顿热饭的人 |
| 终章 | 整理《百味录》，作出自己的承诺 | 回应一路上的行动与遗漏 | 从替祖母办事，转为决定如何与人保持联系 |

### 3.2 四条故事如何编织

三家店各自拥有完整的小故事：人物想要什么、障碍是什么、玩家能参与什么、最后发生什么变化。主角线通过熟悉感、回避的问题、物件记忆与选择反应逐步浮现。

**建议的主角线草案：**主角离乡后忙于自己的生活，和家人的联系越来越像报平安。此次回来，最初把“记下配方”当成可快速完成的任务。三家店逐步让主角发现，自己对故乡与他人的了解停留在过去，也一直用“等忙完再说”推迟联系。最终可以选择留下参与、回到城市保持联系，或暂时只完成记录。是否留下不应直接决定结局好坏。

这条线不必增加重大创伤，也不必靠结尾揭露秘密成立。如果希望采用更强的悬念，需要提前安放可回溯的线索，且不能推翻玩家此前有依据的全部判断。

## 四、人物群像的设计规则

“没有跑龙套的人”落实为：每个具名角色都有自己的生活需要，能提供独有视角，并至少在一个事件中采取行动。角色可以戏份短，但不能只负责发任务或讲道理。

建议每位具名角色填写一张人物卡：

| 项目 | 要回答的问题 |
| --- | --- |
| 当下目标 | 今天具体想完成什么？ |
| 顾虑与代价 | 为什么不能轻易说出口或直接行动？ |
| 表面印象与另一面 | 玩家第一次见到他会怎样理解？后续什么证据会补充这一印象？ |
| 人际关系 | 他在意、依赖、误解或影响了谁？ |
| 自主行动 | 即使玩家不帮忙，他会怎么做？ |
| 玩家影响范围 | 哪件小事可被改变，哪件事需要时间或当事人决定？ |
| 表达特点 | 称呼、说话节奏、动作习惯、幽默感是什么？ |
| 结果回应 | 玩家帮助、拒绝或误判后，他会怎样回应？ |

**建议的初始规模：**每店围绕两位主要关系人物展开，第三章可再增加一位有明确作用的夜归人；加上主角和祖母，先形成可管理的群像。人数需随剧本验证，不以凑足人数为目标。

跨店人物应有实际联系。例如，第一家店的年轻家人也在第二家店帮忙整理订单；第二家店一位不愿用手机点单的熟客，晚上要赶去值班。联系应补充人物处境，不必把所有人都写成彼此认识。

## 五、三章内容方案

以下为可讨论的故事骨架，店名、人名、菜品和具体矛盾均待定。包子铺、面馆可暂作前两章的工作场景，不视为用户已指定。

### 5.1 第一章：一笼早饭与一家人的安排

**已确认主题：**小店烟火气、家庭温情。

**建议冲突：**长辈坚持每日提前开门，认为老客等不起；年轻家人希望调整备餐与休息安排。双方都在关心对方，却一直用自己的方式替对方决定。玩家初见可能误以为年轻人不愿帮忙，随后在排班纸、药袋旁的闹钟、写了一半的备料表中看到另一面。

- 眼前任务：协助准备第一笼早餐，补上《百味录》中一道食物的记录。
- 核心物件：笼屉。磨损、旧修补与叠放习惯都能承载信息。
- 主要玩法：按备餐提示安排蒸笼位置与出笼顺序，在有限空间里兼顾不同订单。
- 叙事联系：玩家亲手发现，改动一个步骤会影响谁能歇一会儿、谁要多等一会儿。
- 关键行动：替一方作决定，或先问清双方安排，再协助一个双方认可的小调整。
- 局部结果：可能达成试行安排、暂时维持现状，或因误传想法造成一次争执；后续仍可留下关心和修复的余地。
- 主角线索：旧笼屉上的记号唤起小时候等早餐的记忆；主角发现自己记得味道，却不记得家人何时开始疲惫。

避免写成“子女必须接班”或“长辈一概固执”。家庭温情可以表现为允许对方休息，也可以表现为接受对方选择另一种生活。

### 5.2 第二章：新订单与老规矩

**已确认主题：**现代化发展与老店熟客销售模式的碰撞。

**建议冲突：**老店接入线上点单后订单变多，厨房产能、熟客习惯和平台显示的出餐时间发生冲突。经营者想活下去，负责新渠道的人也有实际理由，熟客担心自己从“认识的人”变成没人注意的一单。

- 眼前任务：帮忙度过一次订单拥挤，理解不同人的要求。
- 核心物件：擀面杖、手写账本与订单夹。其中擀面杖承担主要小游戏，其余用于解释劳动与经营之间的关系。
- 主要玩法：根据订单与面团状态安排擀制顺序、控制厚薄；重点是读懂需求并作出安排，不单纯比拼手速。
- 碎片信息：旧菜单、取消订单、熟客备注、接单记录呈现冲突原因；私人内容需有可信的查看情境。
- 关键行动：是否先核实各方需求；是否在店主同意后协助尝试限量接单、保留现场点单或预留熟客时段。
- 局部结果：可以形成一次规模有限的试行，也可能因承诺过度导致失约；经营问题不会被一次小游戏彻底解决。
- 主角线索：主角意识到，自己也曾用“这里早该变了”概括故乡，却没有问过变化会影响谁。

避免给“现代化”和“人情”设置天然对立的道德分数。新方式能带来便利，旧方式也可能存在不便；剧情应具体讨论容量、成本、习惯和尊重。

### 5.3 第三章：最后几份热饭

**已确认主题：**深夜为都市夜归人提供晚餐的特殊小馆。

**建议特殊之处：**小馆在固定夜间时段供应有限份热饭，允许有需要的人提前留餐；关门时间明确，店主也要休息。客人既可能是晚下班的普通人，也可能是照顾家人、赶路或临时遇到困难的人。

- 眼前任务：协助留餐、接待最后几位客人并完成收尾。
- 核心物件：保温饭盒、留餐牌或旧台灯，择一作为主要操作对象。
- 主要玩法：根据已知的取餐时间与饮食需要，分装、保温并安排有限餐份；提供查询与确认，避免让玩家盲猜谁更值得帮助。
- 碎片信息：留餐纸条、修补过的饭盒、班次卡和空座位，逐步说明客人为何此时出现。
- 关键行动：是否尊重客人不愿解释的部分；是否擅自替人公开困难；是否在店主同意和自身能力内承担一项具体帮助。
- 局部结果：一份饭顺利交到需要的人手里、一次约定落空，或帮助得到接续。结果应落到具体的人和下一步安排。
- 主角线索：主角回想自己在异乡晚归的经历，第一次愿意承认“我也有过不太好的时候”。

夜归人应具有不同语气、需求与主动行为，避免轮流讲述苦难。店主也不承担无限供应的责任；有人付钱、有人帮忙收桌、有人记得替下一位留一张椅子，都能构成互助。

## 六、碎片叙事与信息拼合

### 6.1 信息分层

| 层次 | 玩家需要理解什么 | 呈现原则 |
| --- | --- | --- |
| 主线必需信息 | 委托是什么、当前发生了什么、下一步能做什么 | 在自然主流程中可获得，不依赖全收集 |
| 分支判断信息 | 某人真实需要、某方案的风险、道具用途 | 做出相关关键选择前存在获取机会 |
| 深层补充信息 | 人物的过去、跨店联系、主角记忆的另一面 | 可错过，能修正理解，不决定基本可通关性 |
| 生活细节 | 口头禅、菜单涂改、店内小习惯 | 提供趣味和可信度，不必全部进入任务系统 |

玩家可以形成不同理解，但不能因为漏点一个小物件就完全不知道剧情在讲什么。人物说的话属于其视角，物件也需要结合语境解释；记录中应区分“已经发生的事实”和“主角目前的猜测”。

### 6.2 一条碎片的完整设计

每条重要碎片应明确：出现位置、获得条件、表面内容、补充的信息、关联人物、可触发的后续对话，以及错过后的影响。

**示例：**第一章发现一张被改过的备餐表，只能得知有人尝试调整开门安排；第二章与年轻家人交谈，才知道改表是为了让长辈休息。第一章记录随后添上一句新理解。第一次观察仍有意义，后续信息也确实改变解释。

避免让一张纸直接写出人物全部秘密，也避免为制造反转而让角色无缘无故隐瞒眼前必须说明的事实。

### 6.3 跨场景补充与回访

**建议：**主要依靠《百味录》旧条目补记、后续人物的新说法和有理由的消息回应完成跨场景联系。少量回访用于值得再次见面的人物事件。

时间关系必须成立：深夜不能无说明地返回清晨营业状态。若不开放物理回访，可在记录中重新查看旧证据，在下一次见面或尾声中处理后续回应。

错过分支与“内容尚未制作”应在创作资料中明确区分。玩家界面只提供合适的当前提示，不展示开发状态。

## 七、核心游玩循环与对话

基本循环：进入场景、注意到人物或物件 → 观察／交谈 → 得到线索或产生新问题 → 动手尝试／使用道具／追问 → 看到人物与环境的回应 → 作出阶段选择 → 《百味录》与任务更新。

每章内部建议包含“初步印象—发现不一致—参与行动—重新理解—承担选择后果”几个节拍，但不强制每章使用相同的反转与菜单结构。

对话可包含：

- 自由询问：了解人、店、菜品和眼前物件。
- 证据追问：结合已知信息提出更具体的问题。
- 态度选择：影响语气与关系，不要求每句都增加数值。
- 行动承诺：答应帮忙、转述信息、提出方案，改变后续事件。
- 关键决定：处理会影响他人意愿、资源、隐私或未来安排的事情。

选项应让玩家大体理解自己要说或要做什么，避免温和选项点下后突然变成攻击。允许拒绝、暂缓和“我还没想清楚”，但在时机确实流逝时，暂缓也可以产生结果。

关键选择前，玩家应知道基本风险；选择后，要尽快看到至少一种可感知的回应。长期影响可在后续章节和尾声补足。

## 八、属性、事件与分支规则

**已确认：**每章积累不同属性，属性直接影响剧情走向与相关结局。小游戏可以带来属性或其他奖励。

**建议：**每章先控制在一至两项有明确含义的属性，再用具体事件记录玩家做过什么。属性与事件共同决定结果，避免用总分取代人物意愿。

| 章节 | 建议属性 | 主要来源 | 可以影响什么 |
| --- | --- | --- | --- |
| 家庭小店 | 倾听：理解双方处境的程度；协作：在获准情况下提供实际帮助的程度 | 询问、核实、劳动参与、履行承诺 | 是否愿意谈计划、能否共同试行安排 |
| 老店经营 | 调研：掌握需求与限制的程度；执行：能否把约定落实 | 查看订单、询问需求、安排操作、完成约定 | 方案是否可提出、试行是否可靠 |
| 深夜小馆 | 体察：注意他人实际需要的程度；照应：提供合适帮助的程度 | 确认需求、尊重边界、留餐与交接 | 是否愿意接受帮助、留餐约定能否兑现 |

这些名称仅用于讨论。可以将“倾听／调研／体察”作为不同章节中理解他人的表现，但不必在界面同时摆出六条进度条。

**属性与事件的区别：**“协作较高”说明长期行为倾向；“未经允许替别人答应提前开门”是具体事件，不能被多玩几次小游戏抵消。

建议的判定方式举例：

- 了解双方需要，才可提出共同试行安排。
- 是否采纳，还取决于当事人是否同意及玩家是否作出相应行动。
- 未获同意就擅自承诺，会走向另一段结果，即使相关属性很高。

数值阈值在事件与可获得奖励定稿后再制定，并逐一核对分支是否可达。不要先填满分数表，再用对白迁就分数。

### 奖励与防止重复刷取

- 首次获得重要证据、完成约定和首次完成小游戏，可以记入一次奖励。
- 重复查看物件或重复同一句对话，不重复增加属性。
- 重玩小游戏可改善操作成绩；对应剧情收益设置上限。
- 操作成绩主要影响物件品质、额外对白或纪念奖励；不单独决定人物是否信任主角。
- 是否显示精确数值待定。建议默认以记录和人物反应表达变化，避免把每句对话变成加分题。

## 九、关键物件与小游戏

每个主要小游戏都需要回答：玩家为什么此时动手、物件为何重要、如何操作、怎样算完成、操作中发现什么、失败后发生什么。

| 工作方案 | 核心操作 | 信息如何进入玩法 | 完成反馈 | 失败处理 |
| --- | --- | --- | --- | --- |
| 笼屉备餐 | 安排位置和出笼顺序 | 备餐习惯体现家人的照顾与劳动压力 | 蒸汽、出笼声、人物接手、备餐表改变 | 提示原因，可重排；剧情失败需另有明确条件 |
| 擀面安排 | 按需求控制厚薄与制作顺序 | 玩家体验订单增长与手工产能的冲突 | 面团形态变化、上餐回应、订单减少 | 可重做或接受普通品质，不因反应慢永久失去主线 |
| 深夜留餐 | 分装、配对、保温与交接 | 阅读留餐提示，理解不同人的作息 | 饭盒被取走、留言或后续确认 | 允许核实与纠正；明确错过时机时进入局部失败 |

建议先为每章设计一个主要小游戏，其余物件提供轻操作、线索、道具用途或生活反馈。数量与复杂度仍待体验确认。

操作原则：规则在场景中说得通；开始前能看懂目标；允许暂停说明；对精细拖拽和连续动作提供点按等替代操作。标准完成足以继续剧情，熟练表现提供额外细节。

**建议：**必经小游戏提供简化操作或协助完成，保留基本叙事体验；高阶操作成就可以单独记录，不让操作门槛吞掉故事。

如果希望限时本身产生叙事压力，应明确这是一次有后果的任务，不能把小游戏操作失误和不可撤回的剧情选择混在一起。

## 十、丰富物件互动的方式

| 互动类型 | 例子 | 主要反馈 |
| --- | --- | --- |
| 主线关键物件 | 笼屉、订单夹、留餐牌 | 开启任务或阶段事件 |
| 叙事物件 | 旧照片、菜单改字、修补过的饭盒 | 获得证据、记忆或可追问内容 |
| 可操作的小物件 | 扶正椅子、拉开抽屉、试敲店铃 | 动作、声音、人物短回应 |
| 道具作用点 | 带来的保温袋可用于留餐 | 解决问题或形成替代路径 |
| 纯生活反馈 | 翻看桌角便签、拨一下挂帘 | 趣味、材质与环境细节 |

建议首轮以每店约八至十二个有区别的互动点估算内容量，其中两三个承担关键推进，其余补充叙事和生活感；最终数量由构图、剧情和试玩决定。

不是每件东西都要弹出文本框。可以用短字幕、物件动画、环境变化和角色一句话回应。关键目标保持可辨认，提供按需热点提示，鼠标、触屏与键盘都能找到并激活目标。

重要状态要有变化：用过的订单被夹到一边，送出的饭盒不再留在桌上，读过的纸条可再次查看。无后续内容时不持续伪装成新任务。

## 十一、道具与收集

| 类别 | 建议例子 | 作用 | 设计约束 |
| --- | --- | --- | --- |
| 探索帮助 | 可借用的手电或夹取工具 | 更方便查看暗处、取出物件 | 缺少时可求助、换时间或采用替代办法，才属于软锁 |
| 后续玩法帮助 | 经同意借出的保温袋 | 扩大后续留餐操作的容错 | 使任务更容易，不应默认成为隐藏必需品 |
| 剧情收集品 | 获赠菜单副页、旧票据复印件 | 支撑人物与跨章联系 | 获得方式合理，不默认拿走他人的私人物品 |
| 任务交接物 | 某位客人托付的饭盒或纸条 | 连接人物与事件 | 说明交给谁、是否消耗、错过有何结果 |

每件重要道具应有名称、来源、描述、持有人、用途、使用反馈、是否可重复使用和失去后的处理办法。

必须使用且没有替代路径的主线道具，应保证在当前分支可获得，不允许先消耗到无关用途后造成卡死。可错过的道具可影响支线结果，但必须与主线可继续相容。

背包与《百味录》职责分开：背包装当前可使用、交付的物品；《百味录》保存已经获得的知识与收集记录。交出去的物品可以留下记录，不再假装仍能使用。

## 十二、《百味录》与成就

### 12.1 《百味录》

**建议：**它是玩家随身的叙事记录与回顾入口，包含三家店的食物记录、人物关系、重要物件、尚待理解的问题，以及主角随进程补写的想法。

新证据可以给旧条目补注，保留“最初以为”和“后来得知”的差别。重要信息保持可查，避免要求玩家记住所有对白。

章节结束时，允许玩家从有证据支持的几种表述中选择如何落笔。例如记录“他们试着换一种开门安排”，或在尚未达成共识时写下“他们还需要一次好好商量”。不让一句选择凭空改写已经发生的事实。

主线所说的“补全”，建议指三家店均形成一份基本记录，并完成终章回应；深层故事与隐藏细节可以仍有空白。游戏应允许玩家理解有限，但愿意继续了解。

### 12.2 成就系统

成就兼顾行动反馈和补充叙事，建议覆盖：

- 观察：发现不起眼的物件变化，获得一条小注释。
- 理解：将两处证据联系起来，解锁人物关系补记。
- 行动：履行一项有前后呼应的承诺，得到具体人物回应。
- 操作：完成较熟练的物件操作，获得纪念图或额外短对白。
- 趣味：触发符合人物性格的小插曲。

成就奖励不承载主线唯一必需的信息；不要求为了全收集必须恶意伤害人物。跨周目成就可保留，但不能使新存档中的主角自动知道从未发现的秘密。

未达成的剧情成就使用模糊名称或隐藏描述，避免在列表中提前公开反转。已获得的记录允许回看，弹出反馈尽量简短，不遮住正在发生的重要对话。

## 十三、任务失败、不可撤销与存档

### 13.1 区分三种失败

| 类型 | 例子 | 建议处理 |
| --- | --- | --- |
| 操作失误 | 擀制未达目标、笼屉排放不合适 | 提示、重试、简化或接受普通表现 |
| 局部任务失败 | 未按约定送到饭盒、擅自承诺导致失约 | 保留结果与后续回应，主线继续 |
| 整局失败 | 委托彻底终止、提前结束旅程 | 是否需要待定；若加入，必须有可理解的原因与恢复入口 |

局部失败也应有内容。人物可以失望、拒绝后续帮助，主角也可以留下不完整记录。避免失败后只剩“请读档”的空白界面。

### 13.2 “不可撤销”的建议解释

建议默认允许读取旧档：一个选择在当前分支中产生持续后果，不能靠反复点击撤销；读取选择发生前的存档，则进入另一条历史。这兼顾选择分量与多结局探索。

如希望禁止读档，需要另行明确为特别模式，不从“不可撤销”直接推导出强制覆盖存档。

### 13.3 保存与恢复规则

- 提供独立的章节自动存档、关键选择前的检查点，以及若干手动档位，具体数量待定。
- 检查点在选择前保存；选择后的自动保存不能覆盖所有可返回的位置。
- 保存章节阶段、对话位置、属性、重要事件、道具、已知线索、任务结果、已发奖励及小游戏完成状态。
- 长小游戏若不能原样恢复，应说明会从本轮开始处重来，并保存进入本轮前的状态。
- 读档后不得重复发奖、重复交付同一道具，或保留来自另一分支的角色知识。
- 新游戏、覆盖存档、清除数据应明确告知影响范围；“返回标题”不清空进度。

尚未决定是否使用联网存档。若采用浏览器本地保存，应向玩家说明保存位置及清除浏览器数据的影响；导入导出存档可作为后续扩展。

## 十四、结局结构

**建议：**先分别结算三家店的局部结果，再呈现主角的最终回应。三个局部结果可组合展示，不必为每种排列制作完全独立的终幕。

结局依据包括：本章相关属性、具体承诺是否履行、当事人意愿、跨章证据，以及终章有依据的最终选择。最终选项只能决定尚未发生的行动，不能洗掉此前后果。

以下是三个主角结局方向，名称和数量均待定：

| 方向 | 应具备的过程依据 | 可能的落点 |
| --- | --- | --- |
| 留下参与 | 了解自己能做什么，获得有关人物同意，愿意承担具体日常 | 主角留下试着参与一段时间，故事以新的日常开始 |
| 带着联系离开 | 已建立可延续的联系或履行过跨店承诺 | 主角回到城市，按实际约定继续联系、记录或帮忙 |
| 暂时合上书页 | 记录较浅、承诺未完成，或主角尚未准备好 | 委托仍留下意义，也留下需要以后回应的缺口 |

留下与离开都可以有温暖或遗憾。结局差别来自理解与行动是否匹配，不把职业和居住选择当作道德判决。

**可选的深层尾声：**当玩家找到足够支撑主角线的证据，并完成相关行动，出现祖母与主角之间更充分的一段交流。建议条件围绕理解与行动，不要求所有小游戏首次完美，也不要求全物件清空。

每个结局要能回答：三家店后来怎样、哪些关系改变、哪些约定得到回应、主角下一步具体做什么。避免只有画面色调和总结文案不同。

定稿时，为每条分支列出必要条件、排除条件、冲突时的判定顺序、正常可达路径。隐藏内容条件不应互相排斥，也不应误覆盖玩家已经达成的另一种结局。

## 十五、美术、界面与声音

### 15.1 美术方向

**已确认：**需要场景、人物、物件素材，以及图标、UI、排版和控件的整体设计。视觉质量与丰富互动共同服务体验。

既有记录中对写实、生活化场景有明确偏好；本次新增的玩法没有决定具体渲染形式。旧稿中的像素风、固定背景或局部3D均不直接视为正式路线。风格和表现方式留待下一阶段讨论。

应先明确统一标准：人物与环境比例、光照方向、材质、色彩、细节密度、字体、图标、按钮状态，以及物件特写与场景原图的对应关系。

| 资源类别 | 内容 | 服务体验的要求 |
| --- | --- | --- |
| 场景 | 序章、三店、终章及必要特写 | 看得清可行动区域，保留交互与文字位置 |
| 人物 | 主要人物外观、表情或姿态变化 | 角色辨识清楚，与对话情绪及站位一致 |
| 关键物件 | 笼屉、擀面杖、饭盒等候选物件及操作状态 | 远景能认出、特写能操作、完成后能看见变化 |
| 叙事小物 | 菜单、照片、账页、便签 | 文字可读，内容与剧情一致 |
| 界面 | 对话、背包、《百味录》、任务、成就、存读档、设置 | 层级清晰，打开后知道如何返回现场 |
| 反馈 | 悬停、聚焦、选中、不可用、完成、失败 | 不仅依赖颜色或细微发光区分 |

主界面建议保留章节／时段与必要入口，避免同时显示全部任务、数值和通知。重要交互不能仅靠精确点击细小区域完成；移动端、键盘和触屏的操作规格需在开发讨论中明确。

### 15.2 音乐与环境声音

建议先覆盖蒸汽、碗筷、店铃、翻页、街道和雨声等具有场景辨识度的声音，再考虑章节配乐。沉默与夜间环境声也可以形成节奏，不必全程铺满音乐。

对白不依赖完整配音成立。提供音乐与音效音量控制；重要信息同时有视觉反馈。静音状态下应仍能完整游玩。

## 十六、幽默与正反馈

**已确认：**希望加入贴近日常生活的幽默、流行表达和小巧思。本次提及的“不烧心”只是方向示例，不是必须植入的台词。

建议优先从店铺生活和人物关系中找幽默：

- 菜单上“微辣”的“微”字被不同人反复圈改。
- 老客说“还是老样子”，店主问“你上周已经换了三个老样子，今天是哪一个？”
- 夜间小馆的纸牌写“本店接受发呆，请给后面的人留个座”。

这些仅是语气样例，须由具体人物和场景决定是否采用。无需为使用当下流行语而强行改对白；涉及人物困难或脆弱时刻，应给情绪足够空间。

正反馈可来自顺手的动作、好听的声音、人物记住玩家的偏好、物件状态变化、旧线索得到解释、承诺被回应，也可以是少量属性与成就奖励。普通互动即时轻反馈，阶段完成较明确反馈，关键剧情保留情绪空间。

## 十七、Wiki与游戏文档

| 文档 | 面向谁 | 建议内容 |
| --- | --- | --- |
| 游戏内帮助 | 初次玩家 | 操作、提示开关、存档说明、卡住时的帮助 |
| 游戏内《百味录》 | 当前存档中的玩家 | 已获得证据、人物记录、问题与补注 |
| 玩家Wiki／攻略 | 主动查询的玩家 | 基础玩法；分区隐藏的任务、成就与结局攻略 |
| 创作设定集 | 编剧、美术、策划 | 世界观、人物关系、时间线、物件来源与视觉规范 |
| 任务与分支表 | 团队制作与验证 | 条件、状态、奖励、失败、替代路径和结局依据 |
| 资源与使用记录 | 团队、展示与交付 | 资产用途、版本、来源与使用说明 |

游戏内记录遵守当前角色知识，不能把完整攻略默认放进来。Wiki可在内容稳定后再补，不抢占主流程和核心体验的制作精力。

## 十八、内容范围与策划验证

这一轮不据旧稿承诺一周工期、特定体验时长或固定资源张数。当前设计的内容量，需在第一段可玩体验中验证后再估算。

**建议优先形成的完整内容：**

1. 序章、三家小馆和终章之间成立的主线因果。
2. 每店一组有自身动机的人物关系、一个关键物件玩法、一次有后果的阶段选择。
3. 一条能够回溯线索的主角故事，以及祖母委托的明确理由。
4. 《百味录》、道具、章节属性、局部任务失败、存读档与结局之间一致的规则。
5. 与实际完成内容相匹配的美术、声音和帮助说明。

更多隐藏支线、趣味物件、跨店回访、成就与Wiki，在上述主干可信、可玩后再扩展。

策划阶段可用以下问题检查文档与剧本：

- 只获取主线必需信息，玩家是否仍理解事件并能完成一次旅程？
- 多探索一处，是否真的得到新理解、可行动机会或有趣回应？
- 每位具名人物是否做过一件体现自身意愿的事？
- 每个关键选择是否有可理解的依据、代价和后果？
- 没有某件可选道具、漏掉某条线索或小游戏表现普通时，是否仍有合理路径？
- 局部任务失败后，人物与记录是否回应这个结果？
- 不读攻略，玩家能否知道当前可做什么，又保留探索空间？
- 三章是否在操作、情绪和冲突上有所区别？
- 结局是否兑现过程，而非突然由一个总分替玩家下判断？

这些问题能检查设计是否自洽；故事是否动人、操作是否有趣、画面是否吸引人，仍须在可体验版本中判断。

## 十九、下一轮优先讨论的决定

建议先讨论前四项，再细化系统与资源规模：

1. **祖母与委托：**祖母目前处于什么状态？为何此时补书？她期待主角带回什么？建议优先考虑可以直接交流的祖母，让结尾有一次真实对话，不默认使用遗愿推动故事。
2. **主角的缺口：**离乡的原因、此次归乡的态度，以及最不愿谈起的问题。可采用“把联系一再推迟”的方向，也可另拟。
3. **每章核心矛盾：**家人具体在争什么、老店遇到哪一种发展压力、深夜小馆究竟特殊在哪里。先定事件，再写主题表达。
4. **结局含义：**希望玩家最后决定居住去向、关系承诺、《百味录》的呈现方式，还是其中几者的组合？主角能影响的范围到哪里？
5. **探索与时间：**章内多自由、可否暂缓、何时离店、能否回访，哪些事件会随时间关闭？
6. **属性与失败：**属性是否显示；哪些行动影响信任，哪些只影响操作成绩；是否需要整局失败？
7. **存档约定：**是否采用“当前分支后果持续，但允许读旧档”的常规方式？
8. **体验规格：**目标游玩时长、主要设备、正式美术路线，以及可承担的角色、互动点和分支数量。

以上确认后，再将策划转换为逐场景剧本、任务分支表、资源清单与开发方案。
