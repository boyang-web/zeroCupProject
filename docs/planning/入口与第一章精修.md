## 入口与第一章

首页以“百味录”为游戏名，使用专门生成的木门、旧书、茶与长明巷画面。背景、街名、书名字形、分隔装饰和菜单分批渐入，只保留开始、继续、存读档与设置。减少动画时直接显示最终状态。

第一章从失业青年回到奶奶家开始。手机中有未完成的简历，信里说明奶奶已知道离职；奶奶因为腿脚与老街变化，把旧食谱搁置了一阵。委托同时承接她自己的心愿与对主角的关心。身体情况只写当下活动限制，未定具体病症、年龄与职业。

当前主流程：看身边物件 → 与奶奶交谈 → 翻开旧书 → 在《百味录》中看第一份食谱 → 整理三张走访书签 → 出门去陈家。照片、信、日历和递茶属于可选接触，漏掉仍能完成第一章。

“小满”保留为当前样段的小名，后续完整人物设定仍可调整。没有把本轮可玩对白视为全部剧本定稿。

## 游玩机制与逐步开放

| 机制 | 玩家怎样接触 | 当前开放时点 | 开发依据 |
| --- | --- | --- | --- |
| 观察与摆弄物件 | 点亮手机、翻照片和日历、展开信纸、翻开旧书 | 第一章开始 | `Interaction.manipulation` 描述动作，动作完成才提交观察命令 |
| 对话与证据追问 | 交谈、根据已看见的物件多问一句 | 第一章 | 条件、对话入口和已有线索统一由规则层判定 |
| 实物拖动 | 将茶具拖到奶奶手边，或用键盘进入物件面板移动 | 第一章可选 | `Hotspot.drag` 描述目标与动作，最终效果走 `interact` |
| 食谱书 | 翻开书页、看食材与做法、新条目落墨、插图显现 | 第一章实际翻开旧书后 | `recipes` 的获得条件，不要求把人物碎片写入早期书页 |
| 随身物与手头的事 | 奶奶交出钥匙，才出现行囊与委托进度 | 接受委托后 | 内容条件控制入口；背包数量仍由核心规则管理 |
| 动手小游戏 | 点选书签，再夹进对应时段；可纠正、求助或退出 | 第一章后半 | 只返回完成或取消，规则层一次性发奖 |
| 重要选择与存档 | 选择前说明会留记录、自动保存检查点 | 第一章第一次重要选择 | 自动、检查点、三个手动档位各自独立 |
| 人间百味 | 问过人物之后，补记一段人生经历 | 第二章局部故事收束后 | 三种局部结果均可解锁，不用操作成绩判定是否有资格了解人 |
| 回访 | 场景快捷入口或菜单选择去过的地方，聊新话题，再回原行程 | 进入第二章即可使用，早于人生记录 | `revisit` / `resume-journey`，保存明确的章与场景返回点 |
| 物件收藏 | 查看互动过的物件、换角度、读详细介绍并发现新碎片 | 第三章进入后 | `collection` 条件与 `study-collection` 命令，不提前泄露物件与文本 |
| 拾零 | 查看已经获得的额外回应与跨章补记 | 人生记录开放后 | 沿用已有成就条件，入口后置 |

这些时点是当前样段的实现安排。后续若改变开放顺序，优先修改 `src/content/progression.ts`，避免在各面板里重新写章节判断。

教学一次只显示一条。可先点其他物件或直接交谈，已完成的步骤会跳过；不要求按提示清空所有可选物品。菜单始终保留基础存读档与设置，主界面不提前排列所有系统。

## 百味录的表现

- 书的打开使用封面三维旋转、书身轻落和纸页展开；下一份记录用独立纸层翻页。
- 第一章仅显示食谱书签。人物页开放后，才出现“人间百味”书签。
- 新记录用本地霞鹜文楷子集逐字落墨，插画由遮罩渐显。它是仿手写的显示效果，未实现真实汉字笔顺描摹。
- 正常重读直接显示内容；新获得条目可播放写入效果。可以立即看完，减少动画时静态显示。
- 游戏事实、奖励与动画分开。关闭书或刷新，不会撤回已获得的食谱，也不会因重新播放动画重复发奖。

## 场景与实物

小院使用背景、人物、前景桌面和桌上物件的层级。桌面以同一背景的遮罩形成前景，遮住人物应在桌后的部分，避免人物贴到桌面上；茶、书、信、照片和手机按画面内实际桌面摆放。花饰只属于菜单装饰，世界物件保持独立精灵。

照片和日历能翻面，信封展开后露出信纸，书封能开合，手机可以点亮、熄灭。翻面也支持水平拖动；茶可以在场景中拖到指定位置。物件完成操作后，再由规则命令发放相应线索。

回访会保留递茶、记事与选择；旧书可切换为打开的状态。进入夜间行程后回院，使用同构图的夜间灯光版本。人物依据当前已发生的事接话，不重新从初次寒暄开始。

## 奶奶的回访链

进入第二章 → 可回奶奶老宅，继续翻物件、讲陈家见闻或问最初记方子的往事 → 返回陈家原房间继续；第二章收束后再开放人生记录，将已经问过的经历呈现于人物页。

第三章进入后，若此前翻过照片，还可以在收藏中细看背板，记下新小字，再回去问奶奶。收藏碎片和人物记述均需实际获得，不因为功能开放就自动知道。

当前收藏已登记第一章的旧书、照片、信、日历、挪过的茶具和手机六件物品。手机的旧备忘还可引出主角第一份工资时与朋友吃饭的片段，补进自己的生活记录。其他章节的物件条目需结合后续新剧情继续制作。

这两段是验证跨章回访与信息接续的内容样段；奶奶的完整生平仍待进一步策划。

## 工程与存档

- `core/conditions.ts`：条件判断；`core/progression.ts`：功能和教学步骤的纯判定。
- `content/progression.ts`：开放顺序、食谱、收藏条目与深层碎片。
- `GameState.journey`：当前主线章和场景。回访不改变这个返回点，不重置任务、背包与决定。
- 内容 v4、状态 v3。旧内容 v3 的第一章提示从精修入口重读；后续章节保留结果并补齐行程。更旧的 v2 先经过原迁移，再进入新迁移。
- 旧数据先完成校验，才执行有意的章节重读。读取不会直接覆盖原文件与手动档位。

## 验证范围

类型、内容与资产引用、规则流程、存档和生产构建分别检查。新增用例覆盖功能开放、第一章无人物页、回访返回点、奶奶的新接话、收藏碎片去重、夜间回院、旧档迁移和方形框角。

浏览器连接仍因宿主环境缺少 `sandboxPolicy` 元数据而未能建立。没有改用其他浏览器控制路径绕过这一限制。本轮尚未完成真实浏览器的布局、翻页观感、触屏拖动、声音与阅读节奏验收；生成图与自动检查均不替代这部分验收。
