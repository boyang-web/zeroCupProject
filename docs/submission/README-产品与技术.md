# 百味录

**一本没有写完的食谱，一次失业后的归乡，一条仍在过日子的老巷。**

《百味录》是一款以“市井烟火·百味人间”为主题的网页叙事探索游戏。玩家扮演失业后回乡的小满，受奶奶委托，走访长明巷的三家小馆，为一本搁置多年的手记补写食谱。

收集方子是这趟行程的起点。随着玩家走进店里、坐下来交谈、帮着做一顿饭，手记中逐渐留下的，还有经营小店的难处、家人之间没有说清的话，以及一个暂时不知道下一步该往哪里走的年轻人。

## 产品介绍

### 从补写食谱开始，走进街坊的日常

故事发生在虚构的长明巷。这里有奶奶住着的老宅、清晨忙着出笼的包子铺、同时照顾堂食与外带的面馆，也有为晚归的人留着灯的小食堂。

小满刚刚失去工作，带着行李和还没整理好的求职草稿回到家中。奶奶请她帮忙续写《百味录》，把几家熟悉小馆的做法重新问清、记下来。于是，一件可以马上着手的小事，让小满重新走出家门，和巷子里的人产生联系。

每家店都有自己的生活节奏。玩家需要在具体的来往中认识他们：什么时候适合开口，谁还没吃上饭，一张留单究竟意味着什么，一个看起来简单的调整又会影响谁。人物会表达自己的想法，也会犹豫、拒绝或作出不同于小满期待的决定。

随着食谱逐页补齐，小满也逐渐有机会面对自己的处境。她的经历与街坊的故事一起，构成这本书里的“百味”。

### 看见、交谈，再亲手参与

游戏将阅读、场景探索和实物操作结合在一起。玩家可以观察房间里的陈设，拿起手机、展开家信、翻看照片和纸页，也可以与人物交谈，了解物件背后的来历。

这些发现会影响后续交流。读过的便条、听过的旧事、已经做过的行动，都可能让人物换一种方式接话；没有问完的话题，也可以在之后的回访中继续。

在小馆里，玩家还会参与与经营日常相连的操作：学习包早饭、按要求分装、理清面馆订单的先后，以及为不同的人核对餐食。这些操作让玩家实际碰到人物正在处理的事情，也为接下来的谈话提供具体的缘由。

## 交互与视听设计

### 让物件成为叙事的入口

游戏采用全视口场景，将人物、可操作物件、家具前景和界面分层呈现。玩家直接选择场景中的实物，进行翻面、展开或拖动；纸张、手机与书页的长文在各自正文区域内阅读。

物件既参与操作，也承载信息。一张照片、一页备料表或一段未发出的求职草稿，分别呈现不同人物的经历和当下处境。对白与观察记录会根据真实发生过的事情变化，避免把尚未听到的私话、尚未完成的行动提前写进手记。

### 一本随着经历逐渐充实的书

《百味录》是贯穿游戏的核心载体。玩家从整理食谱开始，随着行程推进，逐步读到“人间百味”中的人物片段。

书本采用独立封面、叠页、纸纹和翻页动画，文字与插图分别呈现。“人间百味”包含 11 个片段及相应条件版本，按玩家实际发现的顺序收录，每个纸面承载一篇完整的小事；记录内容与玩家经历保持一致。

### 暖木、纸面与长明巷的声音

视觉以暖木、旧纸、桂花和柔和光影为主要元素，让首页、场景、手记与功能界面保持统一。人物和物件使用独立素材，交互时通过轻微上浮、镜头靠近和动作变化给予回应。

声音围绕家中、白天小馆和夜饭三种环境编排原创合成轻配乐，并为翻纸、杯碟和木面等操作提供音效。对白与逐字显字保持安静，为阅读留出空间。

## 游玩与使用

作品可在浏览器中运行，采用自适应布局，支持鼠标、键盘和触屏操作。教学随当前任务逐步出现，玩家可以收起提示，自由探索。

游戏提供自动存档、三个手动档位、存档导入导出、章节重玩，以及音乐、音效、静音、减少动画和全屏设置。玩家可以中断后继续，也可以回到先前的章节重新作出选择。

## 技术实现

《百味录》使用 **Vue 3、TypeScript、Vite、Three.js 与 GSAP** 构建。界面、剧情规则、内容数据和浏览器服务分别组织，未使用 Bootstrap、Element 等预设样式库，木制控件、纸本界面和场景交互由项目自行实现。

### 剧情规则与内容分离

游戏将章节、对白、物件、前置条件和奖励编排为内容数据，由统一规则层处理玩家操作。界面负责呈现结果，不直接修改剧情进度。

这套结构让同一个物件能够根据玩家经历显示不同状态，也让人物记住已经发生的事情。例如，搬走的凳子会离开原位置，尚未听过的故事不会提前进入手记，已经完成的动作不会重复发放奖励。修改对白或替换素材，也不需要重写底层流程。

### 支持中断、回访和旧档接续

存档保存章节位置、对话进度、已发现线索、任务结果与关键选择。玩家中断阅读后可以继续未完成的步骤，回访旧地点后也能返回原来的行程。

读取存档时，程序先检查数据格式与内容引用，再恢复进度；旧版本通过迁移逻辑接入当前内容。开发者测试模式使用独立档位，方便检查不同场景和分支，并与正常游玩进度分开。

### 分层场景与实物交互

场景由背景、独立人物、物件和家具前景组合而成。物件可按剧情阶段改变位置、姿态和可操作状态；镜头靠近、翻面、展开和拖动等表现与剧情规则分开处理。

GSAP 用于镜头与物件转场，Three.js 按需加载，用于部分物件和小游戏的三维表现。小游戏内部处理本轮操作，结束后将完成或取消结果交回统一规则层，避免各小游戏分别维护剧情奖励。

### 渐进阅读与响应式布局

对白、物件说明和纸面文字采用渐进显示，玩家可点按补全或继续；回答在阅读完成后开放，由玩家明确选择。显字进度、翻页位置和教学收起状态独立于剧情存档。

界面根据视口调整场景取景、控件和纸本排版：桌面可并排阅读书页，窄屏切换为单页；长文在正文区域内滚动，边框和常用操作保持固定。减少动画设置用于降低持续运动和阅读等待。

### 资源与运行方式

提交包同时提供源码和生产成品。图片仅在打包副本中转换为等尺寸 WebP，保留透明通道与原有裁切坐标，开发工程原图完整保留。三维模块与小游戏按需加载。

作品无需后端、账号或 API 密钥。安装 Node.js 后，可通过随包静态服务启动成品，无需先下载项目依赖；源码则可独立安装、检查与构建。
